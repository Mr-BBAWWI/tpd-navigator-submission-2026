# 공개 라이브 실행 범위 기록 — 2026-10-02

## 결정 범위

사용자는 저장된 허용 목록 증거를 도구로 분석하고 새 LLM 응답을 생성하는 실제 공개 질의를 명시적으로 승인했다. 이 승인은 기존 D009의 공개 재생 전용 제한과 관련된 과거 AGENTS 문구를 다음 세 작업에 한해서만 좁게 대체한다.

- `candidate_compare`
- `failure_analysis`
- `acceptance_plan`

기존 정적 저장 재생은 계속 접근 가능하다. 이 결정은 일반 목적 모델 API, 임의 입력 실행 또는 상태 변경 승인이 아니다.

## 금지 사항

임의 프롬프트·표적·SMILES, PDF 업로드, 신규 웹 검색, 신규 GPU 계산, 신규 도킹은 금지된다. 사람 승인, M2 기록, 상태 승격은 활성화하지 않는다. 백엔드는 변경 불가능한 동결 공개 영수증만 읽는다.

## 요청 계약

허용된 정확한 본문 형태는 다음과 같다.

```json
{"operation":"candidate_compare","filters":{"parent_id":"선택 사항","e3_type":"CRBN","candidate_ids":["기존 후보 ID"]}}
```

`operation`은 세 허용값 중 하나여야 한다. `e3_type`은 `CRBN` 또는 `VHL`이며 `candidate_ids`는 카탈로그에 존재하는 ID 1~3개만 허용한다. 필터 필드는 모두 선택 사항이다. 본문은 4,096바이트 이하이다.

`GET /api/health`는 설정 여부를 불리언으로 반환한다. `GET /api/catalog`는 공개 후보 324개와 부모 9개를 반환한다.

## 과학적 해석 경계

### 후보 비교

산술과 필터 개수는 결정론적이다. 최대 3개를 표시하며 사전식 선택을 사용하고 가능하면 같은 부모의 CRBN·VHL을 함께 표시한다. 이는 효능, 성공 가능성 또는 실험 우선순위 순위가 아니다.

### 실패 분석

동결 부모 집계는 시도 234, 완료 231, 실패 3, 포즈 제외 91이다. E3·후보 필터는 분석할 부모 집합만 고른다. 이 결과를 E3별 실패 귀속으로 해석해서는 안 된다. 영수증에 없는 실패 원인은 생성하지 않는다.

### 수용 계획

전역 형식 스냅샷은 기준 14개, 통과 3개, 실패 4개, 보류 7개이다. 필터는 후보 문맥 개수만 바꾸고 개별 기준 상태를 변경하지 않는다. 동일 6BOY 홀드아웃 3/5는 실제 수령 자료에서 포함되며 하드코딩 대체값이 아니다. 이 값만으로 형식 승격하지 않는다.

## 모델 및 추적

런타임 워커는 `gpt-5.6-sol`과 고정 DACON Responses 엔드포인트만 사용한다. `store: false`, 최대 출력 1,800, 컨텍스트 최대 15,000바이트, 런타임 제한 85초를 적용한다.

각 응답은 정규 도구 출력과 스냅샷 SHA를 기준으로 생성한다. 도구 추적, 새 UTC 시각, 요청 ID, 요청·반환 모델, 공급자 응답 ID, 사용량, 답변 근거를 반환한다. 엄격한 구조 파싱에 실패하면 성공 답변으로 취급하지 않는다. 실패 응답에 알려진 사용량이 있으면 보존하고, 사용량이 미제공·확인 불가이면 JSON에서 생략한 채 0 또는 추정치로 채우지 않는다.

자동 재시도와 답변 캐시는 없다. 브라우저 제한은 180초이다. 사용자가 브라우저에서 취소해도 공급자 실행이나 과금이 이미 시작되었을 수 있다.

## 보안 및 운영 경계

`DACON_API_KEY`는 서버 런타임 환경에만 두며 클라이언트, Git, 로그, 명령행 인자 또는 파일에 기록하지 않는다. 소스 푸시 자격 증명도 같은 원칙을 따른다. 키 유효성과 공급자 자원 가용성은 종료될 수 있으며 이때 서비스는 명시적으로 실패한다.

`ALLOWED_ORIGINS`는 정확한 출처의 CSV 환경값이다. 동일 출처는 허용하고 `Origin` 없는 POST는 거부한다. 이는 인증 수단이 아니다.

분당 IP 4회와 동시 실행 2회는 격리 인스턴스별 메모리 기반 최선 노력 제한이다. 전역 하드 쿼터나 강한 남용 방지를 제공하지 않는다. 실제 고부하 공개 운영 전에는 영속적인 전역 예산 및 속도 제어가 필요하다.

## 데이터, 테스트 및 배포 상태

백엔드 도우미 구현 검사는 통과한 것으로 확인되었다. 재현 명령은 다음과 같다.

```bash
cd active/submission/live-demo
npm install
npm test
node build.mjs --self-test
npm run build
```

이는 전체 과학적 완료나 실제 배포 성공을 입증하지 않는다. 문서 작성과 구현 검사만으로 공개 배포 성공을 주장하지 않으며, 실제 배포·예제 3개 실행 여부와 현행 파일 해시는 별도의 최신 `live-release-manifest.json` 및 운영 검증 기록을 확인한다.

공개 저장소는 원래 비공개 이력을 보존한 별도 선별 저장소이다. 기존 `source-export-manifest.json`은 V1 동결 페이로드 792개에 대한 원본 매니페스트이며 변경하지 않는다. 새 라이브 릴리스 검토 범위는 별도의 `live-release-manifest.json`이 담당한다.
